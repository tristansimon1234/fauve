# CLAUDE.md — Fauve, l'agent réseaux sociaux des studios

## Produit en une phrase
> **Nom : Brigitte.** Le produit et l'assistante s'appellent Brigitte pour les gérantes (app, WhatsApp, prompts : « Tu es Brigitte »). « Fauve » reste le nom interne du code (repo, routes comme `/fauve`, classes `fauve-*`, composants `Fauve…`, ce document) : ne pas le montrer à l'écran. Mascotte : juste une tête « patate » en flat (sans contour), silhouette de boucles en un seul dégradé violet → corail, yeux qui regardent par-dessus des lunettes demi-lune, sourcil levé ; elle flotte (ombre au sol qui respire), cligne des yeux et lève un sourcil de temps en temps. Humeurs (`mood`) : idle, thinking (pendant qu'elle écrit, `live-typing.tsx`), laugh (quelques secondes quand l'échange est drôle, `isFunny` dans `packages/agent/src/emoji.ts`), happy (nouveau message), shy (un compliment pour elle : rougit, joues rayées, regard de côté, `isSweet`), surprised, sad (déception), angry (reproches, 😡, « !!! », majuscules : sourcils froncés, joues rouges, signe 💢 qui palpite) et cry (mots durs pour elle ou désespoir, 😭 : larmes qui coulent) ; `upsetLevel` dans `emoji.ts` pour les règles ; passage d'une humeur à l'autre en fondu (bouche, yeux) et en glissé (sourcils, regard). Dans le chat, une seule Brigitte en grand en haut à gauche de la conversation (avec son nom et ce qu'elle fait) (`BrigitteLive` dans `fauve/brigitte-avatar.tsx`, 60 px, 44 px sur téléphone, aussi dans l'en-tête du panneau Fauve) : elle réfléchit pendant qu'elle écrit, puis réagit au dernier message. Réaction instantanée : à chaque message de l'app, Jev (modèle de décision de TypeSafe, `@typesafe-ai/sdk`, `lib/agent/mood.ts`, questions en anglais, détaillées, dans `packages/agent/src/mood.ts`) choisit en parallèle du modèle de chat sa tête (rire, contente, timide, surprise, triste, énervée, pleure, neutre) et un emoji éventuel sur le message ; l'événement `mood` arrive avant sa réponse (`chatTurn` → `instantReaction`), l'emoji est gardé sur le message. Sans `TYPESAFE_API_KEY`, repli sur les règles (`isFunny`, `upsetLevel`), sans emoji. Personnalité dans le prompt : chaleureuse, franche, l'œil expert, un brin malicieuse, de l'humour quand la gérante en fait (`components/mascot.tsx`, aussi dans le logo et `app/icon.svg`).

Fauve est une community manager IA qui vit **dans WhatsApp**. La gérante d'un commerce de quartier (studio de Pilates ou de yoga, salon de coiffure, restaurant, boutique…) envoie ses vidéos, et Fauve les monte, écrit les légendes, programme sur Instagram et TikTok, relance quand il manque un contenu, et fait un bilan chaque semaine. Une petite web app (desktop + mobile) sert à voir le calendrier, valider, déposer des vidéos en pleine qualité et suivre les résultats.

- Prix : deux offres, **Essentiel 29 € / mois** (80 crédits, rythme de 2 publications par semaine) et **Pro 49 € / mois** (150 crédits) ; un studio en essai a Pro (`packages/agent/src/plans.ts`, `studios.plan`, `planOf`). Pour l'instant on optimise la **qualité et la vitesse**, pas les coûts, mais on **journalise le coût par studio dès le jour 1**.
- Interface en français ; code, tables et commits en anglais.
- Maquette de référence : canvas Design « Agent studios — Maquette » (app : Fauve, Calendrier, Publication, Résultats ; onboarding : Landing, WhatsApp, Connexion Instagram, Compte prêt).

## Stack

```
Gérante ──WhatsApp──▶ Meta WhatsApp Cloud API ──webhook──▶ apps/web (Next.js, Vercel)
                                                              │  agent (Claude, tool use)
                                                              ├─▶ Supabase (Postgres, Auth, Storage, Realtime)
                                                              ├─▶ jobs (Inngest ou Trigger.dev) : relances, rendus, publication, stats
                                                              ├─▶ analyse vidéo (Gemini) ─▶ plan de montage JSON (Claude)
                                                              ├─▶ worker de rendu (ffmpeg / Remotion, hors Vercel)
                                                              └─▶ publication (Ayrshare au MVP ; API Instagram / TikTok en direct ensuite)
```

- **Vercel** : Next.js (App Router, TypeScript strict, Tailwind). Pages, API routes, webhook WhatsApp. Rien de long ou de lourd ici (pas de ffmpeg).
- **Supabase** : Postgres + RLS, Auth par téléphone, Storage pour les médias, Realtime pour rafraîchir la web app.
- **Jobs** : Inngest ou Trigger.dev pour tout ce qui est planifié ou long (relances, rendus, publication à l'heure, collecte des stats). `pg_cron` acceptable pour les tâches simples.
- **Worker de rendu** : un service séparé (Fly.io ou Railway) avec ffmpeg, ou Remotion Lambda. Il reçoit un plan de montage JSON et renvoie un fichier.

Monorepo :
```
apps/web        Next.js (app + landing + API + webhook WhatsApp)
apps/render     worker de rendu (ffmpeg, Node ou Python)
packages/agent  prompts, définitions des tools, schémas Zod (plan de montage, post…)
supabase/       migrations, seed (gabarits, types de contenu)
```

## WhatsApp (Meta Cloud API en direct, sans Twilio)

- **Un seul numéro, celui de Fauve**. Toutes les gérantes écrivent au même numéro ; le studio est retrouvé par le numéro de l'expéditeur.
- Webhook : `POST /api/whatsapp/webhook` (vérification de signature `X-Hub-Signature-256`, idempotence sur l'id de message).
- **Fenêtre de 24 h** : réponse libre gratuite tant que la gérante a écrit dans les dernières 24 h. Au-delà, **uniquement des modèles validés par Meta** (payants). Prévoir dès le départ une petite liste de modèles :
  - `content_request` : « J'ai besoin de {quoi} pour le post de {jour}. Tu peux me l'envoyer ? »
  - `draft_ready` : « Ton {type} pour {jour} est prêt. Je le programme ? »
  - `weekly_report` : « Ton bilan de la semaine est prêt. »
  - `login_code` (catégorie authentification) : code de connexion.
- **Naturel** :
  - marquer comme lu + indicateur « en train d'écrire » dès réception ;
  - **réactions emoji** pour les accusés de réception simples, avec un vocabulaire fixe : 👍 reçu, 🔥 super contenu, ✅ publié. Jamais sur chaque message ; une question appelle toujours une vraie réponse ;
  - Fauve est transparente sur le fait d'être une IA.
- **Médias** : télécharger chaque média reçu vers Supabase Storage. WhatsApp compresse les vidéos : Fauve invite à envoyer les clips **en tant que document**, ou à passer par le lien de dépôt de la web app pour les gros fichiers.

## Connexion (téléphone, sans mot de passe)

Supabase Auth en mode **téléphone + code** :
- le code est envoyé **par WhatsApp** (modèle `login_code`) via le **Send SMS Hook** de Supabase (livraison personnalisée), SMS en secours ;
- **lien magique** : chaque lien envoyé par Fauve contient un jeton opaque, à usage unique, valable 15 min, lié au numéro. La route `/auth/link/[token]` vérifie le jeton côté serveur et ouvre la session (cookies `@supabase/ssr`) ;
- **QR code sur ordinateur** (comme WhatsApp Web) : l'ordi affiche un QR lié à une demande de connexion ; le téléphone déjà connecté le scanne et confirme ; l'ordi reçoit la session via Realtime ;
- liste des sessions ouvertes, déconnexion à distance ; confirmation WhatsApp pour les actions sensibles (déconnecter Instagram, changer de paiement).

Vérifier dans la doc Supabase à jour la meilleure façon d'ouvrir une session côté serveur pour un utilisateur téléphone : ne pas se fier à sa mémoire.

## Connecteurs Instagram / TikTok

**MVP : un agrégateur, pour ne pas attendre les validations.** Ayrshare couvre 13 réseaux (dont Instagram, TikTok, Google Business Profile), gère l'autorisation OAuth de chaque compte, l'hébergement des médias et le multi-comptes pour les SaaS. Alternatives à évaluer : Upload-Post, Late, Postiz (open source, auto-hébergeable).
- un « profil » agrégateur par studio ; la page `/connect` (étape 2 de l'onboarding) ouvre leur flux de connexion ;
- publication programmée, statistiques et commentaires passent par le même fournisseur.

**Ensuite : API officielles en direct**, pour les coûts et la maîtrise :
- **Instagram** (compte professionnel requis) : API Instagram avec connexion Instagram ; publication de photos, carrousels, Reels et stories ; lecture des statistiques ; messages et commentaires. Nécessite la **revue d'app Meta** (vérification d'entreprise, démo vidéo) : la lancer tôt, elle prend des semaines.
- **TikTok** : Content Posting API. **Tant que l'app n'est pas auditée, les publications restent privées.** Alternative : envoyer dans les **brouillons TikTok** de la gérante, qui publie elle-même.

Limites à connaître : la **musique tendance** et les **stickers interactifs** (sondages, questions) ne sont pas disponibles par API. Fauve les suggère, la gérante les ajoute dans l'appli au moment de publier.

## IA : le meilleur modèle pour chaque rôle

- **Cerveau de Fauve : Claude (`claude-opus-5-5`) partout pour l'instant.** Conversation WhatsApp, planification des campagnes, légendes, profil de style, plan de montage, bilans. Tool use avec schémas Zod stricts.
- **Analyse vidéo : Gemini 3.7 Flash** (entrée vidéo native, horodatages, mode « agentic video understanding » qui choisit quoi regarder). Il reçoit les clips et renvoie, en JSON : découpage en plans, horodatages, qualité (flou, sombre, bougé), ce qui se passe, transcription si voix.
- **Rendu : outils déterministes**, jamais le modèle directement. Le modèle **décide**, le moteur **exécute**.
- À tester plus tard : Gemini Omni Flash (montage vidéo conversationnel), mais seulement si la qualité est constante.
- Toujours vérifier les noms et capacités des modèles dans la doc à jour avant de coder.

### Pipeline vidéo
1. Clips reçus (WhatsApp ou dépôt web) → Storage.
2. Gemini analyse chaque clip → `clip_analysis` (JSON).
3. Claude choisit les plans, l'ordre, l'accroche des 2 premières secondes, le gabarit, les textes et leur timing → **plan de montage JSON** (`edit_plan`, validé par Zod, versionné).
4. Worker de rendu : JSON → MP4 9:16 1080×1920 (Reels/TikTok) + variantes (story, carré, carrousel de captures).
5. Aperçu envoyé sur WhatsApp et dans la web app. Une correction (« enlève le 2e plan », « texte plus gros ») **modifie le JSON**, puis on relance le rendu.

Règles de montage : coupes franches (fondu ou léger zoom ponctuels seulement), 7 à 15 s, accroche dès la 1re seconde, sous-titres mot à mot, logo en fin, **zones de sécurité** (pas de texte en bas ni à droite).

Schéma minimal du plan de montage :
```json
{ "format": "9:16", "duration": 12, "template": "class_of_the_day",
  "segments": [{ "clip_id": "…", "in": 1.2, "out": 3.0, "zoom": "none|light" }],
  "texts": [{ "text": "…", "from": 0, "to": 2.5, "style": "hook|band|caption" }],
  "images": [{ "asset_id": "logo", "position": "bottom_right", "from": 9, "to": 12 }],
  "transitions": "cut", "subtitles": true, "music": null }
```

### Images (texte sur photo)
Gabarits **HTML/CSS** à la charte du studio (planning de la semaine, nouvel atelier, citation, témoignage, places restantes), rendus en image (Satori/@vercel/og ou Playwright côté worker). Le modèle choisit le gabarit et le texte ; il ne dessine pas.

## Le cycle de l'agent

1. **Onboarding dans WhatsApp** : nom du studio → rythme (ex. 3 posts + 4 stories / semaine) → 2-3 posts d'exemple → lien de connexion Instagram (+ TikTok) → « compte prêt ».
2. **Profil de style** : tirés des exemples (ton, longueur, emojis, hashtags, visuels). Chaque correction de la gérante l'affine (`brand_profile`, versionné).
3. **Campagne** : calendrier du mois avec des thèmes récurrents (cours, coulisses, profs, témoignages, offres, conseils Pilates) et les temps forts (rentrée, janvier, avant l'été, ateliers).
4. **Liste de tournage** hebdomadaire : quoi filmer, avec angle et lumière conseillés.
5. **Relances** : la veille de chaque publication s'il manque un média ; plan B (bibliothèque, post texte) si rien n'arrive.
6. **Production → validation → publication** : rien n'est publié sans validation au début.
7. **Bilan du dimanche** : ce qui a marché, pourquoi, et les ajustements du calendrier.

### Statuts d'un post (machine à états)
`planned → content_requested → media_received → draft → validated → scheduled → published → measured`
(+ `skipped`, `failed`). C'est ce statut qui décide des relances.

### Tools de l'agent
`get_studio_context`, `get_calendar`, `create_post`, `update_post`, `request_content`, `analyze_clips`, `quote_montage`, `montage`, `render`, `send_preview`, `schedule_post`, `get_metrics`, `draft_reply` (commentaires/DM), `update_brand_profile`, `react_to_message`.

## Web app

Écrans (voir maquette) :
- **Fauve** : accueil « ce qui t'attend » + conversation. Le canal principal reste WhatsApp : bouton « Continuer sur WhatsApp », et l'historique sert surtout à retrouver une demande.
- **Calendrier** : semaine, statut par post, filtres, liste « À filmer », progression du rythme.
- **Publication** : aperçu Instagram / TikTok, légende, plateformes, horaire, plan de montage, explication de Fauve, Valider.
- **Résultats** : 7 / 30 jours, avec en premier les **réservations venues d'Instagram**, puis le bilan de Fauve, les meilleurs posts et les meilleurs moments.
- **Médiathèque**, **Réglages** (comptes, rythme, style, sessions, abonnement Stripe).
- Onboarding web : **Landing** (CTA « Commencer sur WhatsApp » + QR code), **Connexion Instagram**, **Compte prêt**.

Responsive : desktop d'abord pour la web app (le dépôt de vidéos et le calendrier y sont plus confortables), parfait sur mobile pour les pages ouvertes depuis WhatsApp. PWA installable.

## Droits et conformité
- **Droit à l'image** : `media_assets.consent_ok`. Fauve rappelle d'avoir l'accord des élèves filmés, et propose des cadrages sans visage (mains, pieds, machines) ou le floutage.
- RGPD : données hébergées en Europe, suppression complète quand un studio part, contrat de sous-traitance avec chaque studio.
- Musique : aucune musique protégée intégrée au rendu ; son tendance ajouté dans l'appli, ou bibliothèque libre de droits sous licence.

## Conventions

Les liens d'une publication (`open_post`) valent 24 h au lieu de 15 min, toujours à usage unique ; ouvrir le lien (GET) ne consomme rien : une petite page envoie un formulaire (POST) par script, et seul ce POST ouvre la session, pour que les robots d'aperçu de lien (WhatsApp, Facebook…) ne l'utilisent pas avant la gérante ; un lien déjà utilisé ou expiré mène directement à la page si la session est encore ouverte.
- La maquette décompressée (un HTML par écran) est dans `docs/maquette/ecrans/`.

- Analyse vidéo : `apps/web/src/lib/video/analyze.ts` (Gemini, `GEMINI_MODEL`, un seul passage par clip via `media_assets.analysis_status`) ; outil `analyze_clips`.
- Montage : outil `montage` → tâche de fond `/api/jobs/montage` en deux invocations (design puis rendu + envoi). Le monteur Opus (`apps/web/src/lib/agent/editor.ts`, prompt et normalisation dans `packages/agent/src/editor.ts`, effort high, sortie structurée) écrit le plan ; les scènes libres de motion design sont codées par le motion designer Opus (`apps/web/src/lib/agent/motion-designer.ts`, contrat et contrôles dans `packages/agent/src/motion-scene.ts`), testées dans la sandbox (`apps/render/smoke.mjs`) avec une scène fixe de secours.
- Rendu : gabarits de motion design Remotion `doux` / `dynamique` / `chic` dans `apps/render` (hors workspaces npm ; après modification, `npm run render:pack` régénère `apps/web/src/lib/render/remotion-source.generated.ts`, vérifié en CI). Props calculées par `packages/agent/src/motion.ts`. Exécution dans une Vercel Sandbox persistante `fauve-render` (`apps/web/src/lib/render/sandbox.ts`), avec repli sur le moteur ffmpeg (`packages/agent/src/render.ts`). Outil `render` : rendu après la réponse (`afterReply`). À la livraison (`lib/render/deliver.ts`), Fauve n'envoie pas la vidéo : un lien de connexion vers la page de la publication sur WhatsApp (`lib/auth/login-link.ts`), une carte dans l'app, qui ouvre la page (`payload.open_post`).
- Charte, source unique des polices et des couleurs : la charte du commerce (Style, `brand_profiles.fonts` titres puis texte, `colors` la principale d'abord) décide de tout ; le gabarit (« Ambiance » à l'écran) ne fait que le rythme, les transitions et les apparitions, ses polices ne servent que si la charte n'en a pas (la lecture du site en propose toujours deux, `moodboardReadingSchema.fonts`). Un style de texte nomme les polices et couleurs par leur rôle (`brand_display`, `brand_body` ; `accent`, `accent_ink`, `secondary`, `light`, `dark`), changés en vraies valeurs à la préparation du rendu (`resolveBrandLook`, `brandLooks` dans `motion.ts`, palette `brandPalette` dans `text-look.ts`, `ReelInputs.brand.colors`) : il suit la charte quand elle change. Une police précise n'est gardée que pour refaire un exemple.
- Tes créations (`/composants`, « Créations » dans le menu) : trois onglets, Styles de texte (la charte, les styles enregistrés, retirables, et les 6 styles prêts à l'emploi tirés de la charte : `text-styles.tsx`), Éléments pour photos (les composants) et Animations (scènes des Reels, `CreationsSection`). La Médiathèque ne garde que les photos et vidéos.
- Édition simple pour les non-pros : un texte se règle par ses mots, un style en un clic (`components/montage/style-picker.tsx` : vignettes dessinées dans chaque style, styles enregistrés du studio puis 6 styles prêts tirés de sa charte, « Simple » = celui du gabarit, « Actuel » = un style fait pour ce texte ; une vignette joue l'apparition du texte au survol ou quand elle est choisie), sa taille (A−/A+) et sa place en le faisant glisser sur l'aperçu ; plus de rôle, de curseurs de temps ni de réglages de police : le reste se demande à Brigitte. Chaque nouveau style créé par `style_texts` est enregistré dans les styles du studio.
- Éditeur de scènes (page Publication, `montage-editor.tsx`), en trois colonnes sur ordinateur : la publication à gauche (légende, date, note de Fauve), au centre l'aperçu sur une scène sombre et la timeline (un bloc par scène, largeur = durée, glisser pour réordonner ; piste des textes ; tête de lecture), à droite l'inspecteur de la scène choisie (avancer/reculer/supprimer, champs, textes, « Demander à Fauve »). Détails : le montage joue en direct dans le navigateur avec `@remotion/player` et la composition du worker (`@render/*` → `apps/render/src`, alias Turbopack dans `next.config.ts` pour une seule copie de React et Remotion). On attrape les textes sur l’aperçu pour les placer (x, y dans la zone de sécurité, repérés par `data-fauve-text`), on change leur contenu, style, taille et fond, ordre, durée, découpe des vidéos, textes des animations ; les textes suivent leur scène (`packages/agent/src/plan-edit.ts`). « Enregistrer » (`saveEditPlan`) crée une nouvelle version du plan et relance le rendu, gratuitement ; le code des animations ne peut pas venir du navigateur.

- Conservation des médias : une photo ou vidéo reste tant qu'une publication en a besoin, puis est supprimée 24 h après sa mise en ligne (`posts.published_at`, posé par un trigger), ou au bout de 7 jours si aucune publication ne l'utilise (`expired_media()`, qui regarde `media_ids`, `post_media`, les clips des plans et les photos des slides). `/api/cron/retention` (pg_cron `fauve-retention`, toutes les heures) supprime les fichiers puis les lignes. Les rendus finaux restent.
- Transitions (React `<ViewTransition>`, API View Transitions du navigateur ; CSS `fauve-*` à la fin de `globals.css`, coupées si l'appareil demande moins de mouvement) : chaque page de l'app entre en fondu avec une légère montée (`app/(app)/template.tsx`, le menu ne bouge pas : la racine ne fait pas de fondu) ; le squelette de chargement s'efface et le contenu monte (`components/page-suspense.tsx`, `PageSuspense` au lieu de `Suspense` + `PageLoading`) ; au calendrier, la semaine glisse du côté d'où elle vient (`Link transitionTypes` `week-prev` / `week-next` / `week-today`, `ViewTransition key` sur la semaine) ; Semaine ⇄ Grille et les onglets de Créations se fondent (`fauve-fade-swap`). Une nouvelle page passe par `PageSuspense` ; un changement de contenu au même endroit, par un `ViewTransition key` avec `fauve-fade-swap`.
- Fluidité : `StudioLive` (`components/studio-live.tsx`, monté dans le layout `(app)`) écoute en Realtime `posts` et `media_assets` du studio et rafraîchit la page ouverte (groupé, rattrapé au retour sur l'onglet) : ce que Fauve ou une tâche de fond change apparaît partout. Les éditeurs qui gardent une copie locale (légende, montage, carrousel, page `/v`) ont une clé `versionKey(...)` (`lib/version-key.ts`) : ils repartent de la version du serveur quand elle a changé ailleurs. Le calendrier remplace ses déplacements locaux par ce que le serveur renvoie. Les liens signés des médias sont gardés une heure (`signMediaUrls`, `use cache`) : un rafraîchissement ne recharge pas les images.
- Mises en page souples : sur l'aperçu du carrousel (`components/montage/layer-handles.tsx`), on clique sur un texte d'une mise en page pour l'écrire sur place (`inline-edit.tsx`, aussi sur les textes libres via `TextBoxes onEdit`, dans l'éditeur de scènes et la page `/v`), on glisse le bloc pour le déplacer et on tire le coin pour l'agrandir (`layer.place`), on change sa couleur (`layer.accent`) ; `TextLayer` applique place et couleur au rendu. Les cases vides prennent les textes d'exemple de la mise en page (`motion_templates.sample`), jamais la description du champ. Dans le panneau, « Que veux-tu sur cette photo ? » (`photo-ask.tsx`) envoie la demande à Fauve pour cette photo, avec un exemple joint au besoin.
- Monteur : sa sortie structurée nomme un style enregistré (`look_name`) au lieu de le recopier (le schéma complet des looks rendait la grammaire trop grande pour l'API, erreur 400) ; `fromEditorPlan` remet le look, `carryTextStyle` garde les styles et places des textes d'une version à l'autre. `quote_montage` ne lance un petit nouveau montage tout seul que si `go` est vrai (la gérante l'a demandé) ; une correction ou une variante ne part jamais toute seule (une critique n'est pas un accord) : le devis attend « Lancer ».
- Suivi des travaux (`studio_jobs`, `lib/studio-jobs.ts`, étapes dans `packages/agent/src/jobs.ts`) : chaque montage (même id que son devis, étapes recopiées par `setQuoteStage`) et chaque calque de texte (`design_text_layer` crée le job, `/api/jobs/text-layer` le fait avancer : dessin, relecture, correction, images finales) a sa ligne.
