# Écrans de l'app

Le menu et la Grille, les Réglages, la page Edith, les transitions et la fluidité (`PageSuspense`, `StudioLive`, `versionKey`).

Détail déplacé de CLAUDE.md le 4 novembre 2026, mot pour mot : un paragraphe par fonction. Quand une fonction change, son paragraphe change ici.

- Pas de calendrier ni de liste de tâches dans l'app (« un bonbon, pas une pièce montée ») : `/calendrier` et `/publications` mènent à la Grille, qui montre ce qui est prévu ; l'outil `request_content` (liste « À filmer ») est retiré ; la page Edith propose « Une idée pour cette semaine ». Le code du calendrier reste dans `app/(app)/calendrier/` sans page. Avant : Menu (`components/app-nav.tsx`) : Fauve, Calendrier (vues Semaine | Grille via `?vue=grille`, toutes les publications ; `/publications` y redirige), Grille (`/grille`, sa propre page avec « Créer une publication », `lib/grid.ts`), Résultats, puis Médiathèque, Composants et Style, puis Réglages. Sur téléphone la barre garde 5 entrées et Médiathèque / Composants / Style s'ouvrent depuis les onglets de Réglages (`components/settings-tabs.tsx`). Calendrier : bandeau À valider / À filmer / Rythme, semaine sur toute la largeur avec vignettes (`lib/covers.ts`), annulées masquées (filtre « Annulées ») ; glisser une publication sur un autre jour (`movePost`, heure locale gardée), + sur un jour pour une idée (`addPost`), clic = panneau latéral (`post-drawer.tsx`, `getPostSheet`). Actions groupées : cocher (ou Ctrl/⌘ + clic) puis la barre du bas valide, déplace à une date ou supprime (`validatePosts`, `movePosts`, `deletePosts`) ; glisser une publication cochée déplace toute la sélection du même nombre de jours.
- Réglages en onglets sur ordinateur aussi (Tristan : « page reglages il faudra la mettre sous forme d'onglet aussi ») : Mon commerce (ses infos, « Ce qu'Edith sait de ton commerce », Rythme), Réseaux (Comptes connectés), Montages (Soin des montages, Style des vidéos), Abonnement et crédits, Mon compte (avec « Me déconnecter ») ; l'onglet dans l'adresse (`#reseaux`), une section liée d'ailleurs ouvre son onglet (`#credits`, `ANCHORS`) ; une adresse changée par un lien de l'app (pushState, sans hashchange) est vue par la Navigation API là où le navigateur l'a ; sur téléphone, les sections à la suite (`reglages/settings-panels.tsx`).
- Grille : ses profils tels qu'on les voit dans les applis (Tristan : « tu peux reproduire réellement les comptes insta / tik tok ? ») : une carte de la largeur d'un téléphone, dans la police des applis. Instagram : son nom d'utilisateur en haut, sa photo, son nom et ses trois compteurs, sa bio (activité en gris, texte, lien de son site), « Modifier le profil » / « Partager le profil » dessinés, onglets en icônes seules (grille, Reels, identifications dessinée ; `grille/grid-tabs.tsx`), grille serrée en 3:4 (9:16 dans Reels, avec les vues) et le petit pictogramme blanc des applis pour un Reel ou un carrousel. TikTok : nom en haut, photo centrée, @, Abonnements / Followers / J'aime, boutons, bio (`bio_description`), onglets (vidéos, privées et j'aime dessinés), vidéos en 3:4 avec leurs vues. Le titre, « Créer une publication », la phrase, le choix Instagram / TikTok et la ligne pour relier un compte sont dans une colonne à gauche du profil sur ordinateur, au-dessus sur téléphone (Tristan : « tous les trucs ici mets-les plutôt sur le côté » ; `GridLayout` dans `grille/platform-switch.tsx`). Pas encore relié : le même profil avec le nom, l'activité, le site et le logo de son commerce (`profileIdentity` dans `lib/grid.ts`) et une ligne au-dessus pour le relier, plus de carte vide à la place. Les publications prévues sont à leur place, marquées seulement par une petite étiquette en bas (statut et jour), sans cadre pointillé. Avec TikTok proposé, un bouton Instagram / TikTok (`grille/platform-switch.tsx`) : le profil TikTok (`loadTikTokGrid` dans `lib/grid.ts` : abonnements, abonnés, j'aime, vidéos en 3:4 avec leurs vues et leur couverture `cover_image_url`, jamais gardée), les Reels prévus avec TikTok en premier puis ceux en attente dans ses brouillons (« Dans tes brouillons »).
- Transitions (React `<ViewTransition>`, API View Transitions du navigateur ; CSS `fauve-*` à la fin de `globals.css`, coupées si l'appareil demande moins de mouvement) : chaque page de l'app entre en fondu avec une légère montée (`app/(app)/template.tsx`, le menu ne bouge pas : la racine ne fait pas de fondu) ; le squelette de chargement s'efface et le contenu monte (`components/page-suspense.tsx`, `PageSuspense` au lieu de `Suspense` + `PageLoading`) ; au calendrier, la semaine glisse du côté d'où elle vient (`Link transitionTypes` `week-prev` / `week-next` / `week-today`, `ViewTransition key` sur la semaine) ; Semaine ⇄ Grille se fondent (`fauve-fade-swap`). Une nouvelle page passe par `PageSuspense` ; un changement de contenu au même endroit, par un `ViewTransition key` avec `fauve-fade-swap`.
- Fluidité : `StudioLive` (`components/studio-live.tsx`, monté dans le layout `(app)`) écoute en Realtime `posts` et `media_assets` du studio et rafraîchit la page ouverte (groupé, rattrapé au retour sur l'onglet) : ce que Fauve ou une tâche de fond change apparaît partout. Les éditeurs qui gardent une copie locale (légende, montage, carrousel, page `/v`) ont une clé `versionKey(...)` (`lib/version-key.ts`) : ils repartent de la version du serveur quand elle a changé ailleurs. Le calendrier remplace ses déplacements locaux par ce que le serveur renvoie. Les liens signés des médias sont gardés une heure (`signMediaUrls`, `use cache`) : un rafraîchissement ne recharge pas les images.
- Page Fauve : trois raccourcis (« Créer une publication » ouvre `NewPostSheet`, « Voir mes derniers résultats », « Voir ce qui m’attend » avec le nombre à valider et à filmer).
- Menu de gauche fixe (Tristan, 6 novembre : « la side bar ne reste pas statique ») : sur ordinateur, le menu (`AppShell`, `components/app-shell.tsx`) est posé en `fixed` sur la hauteur de l'écran, et le contenu décalé de sa largeur (`lg:ml-[232px]`) ; en `sticky`, il ne restait en place que dans la hauteur de son parent, et partait avec la page dès qu'elle la dépassait. Il défile seul s'il est plus haut que l'écran.
